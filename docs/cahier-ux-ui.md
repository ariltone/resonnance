# RÉSONANCE

### CAHIER UX/UI ET DIRECTION ARTISTIQUE

Version 1.0 — Document de conceptionStatut : Document de référence

## 1. Objet du document

Le présent document définit les principes d'expérience utilisateur, d'interface et de direction artistique de RÉSONANCE.

Il précise :

- la manière dont le joueur entre dans l'expérience ;
- la structure des écrans ;
- les parcours et transitions ;
- les interactions ;
- la place accordée aux images ;
- le rythme visuel ;
- l'ambiance générale ;
- les principes graphiques ;
- la typographie ;
- les animations ;
- les règles d'accessibilité ;
- les comportements sur mobile et ordinateur ;
- les principes de cohérence visuelle.

L'objectif n'est pas de construire une interface spectaculaire.

L'objectif est de créer une interface qui disparaît suffisamment pour laisser place à l'expérience.

## 2. Principe UX fondamental

RÉSONANCE ne doit pas ressembler à une application traditionnelle.

Il ne doit pas donner l'impression de :

- remplir un questionnaire ;
- consulter un tableau de bord ;
- passer des niveaux ;
- répondre à un test ;
- naviguer dans un logiciel.

Le joueur doit avoir le sentiment d'entrer dans un espace.

L'interface devient le cadre de l'expérience.

## 3. Le principe de présence

L'écran doit donner une impression de calme, de disponibilité et d'espace.

Le joueur doit pouvoir :

- regarder ;
- hésiter ;
- revenir ;
- choisir ;
- rester quelques secondes sans être pressé.

Le système ne doit pas constamment solliciter son attention.

Éviter :

- notifications agressives ;
- compteurs ;
- badges ;
- barres de progression anxiogènes ;
- animations permanentes ;
- boutons omniprésents.

## 4. Une expérience principalement visuelle

Le cœur de RÉSONANCE est visuel.

L'image doit pouvoir occuper une place importante dans l'écran.

Lorsqu'un choix d'image est demandé, les éléments secondaires doivent disparaître autant que possible.

Le joueur doit avoir devant lui :

le texte

puis

les images

puis

son choix.

Rien ne doit concurrencer ce moment.

## 5. Architecture générale de l'expérience

Le parcours utilisateur est organisé autour de quelques espaces fondamentaux :

- Accueil
- Entrée dans une partie
- Résonance
- Choix
- Expression
- Mise en perspective
- Carnet
- Clôture

Cette structure doit rester invisible autant que possible pour le joueur.

Il ne doit pas avoir l'impression de changer de « module ».

## 6. L'accueil

L'accueil doit être minimal.

Il doit présenter :

- le nom RÉSONANCE ;
- une phrase courte ;
- une invitation à commencer ;
- éventuellement l'accès au carnet.

L'écran ne doit pas expliquer toutes les règles.

Le joueur doit découvrir progressivement le fonctionnement.

## 7. Entrer dans une partie

Le lancement doit être extrêmement simple.

Exemple :

RÉSONANCE

Prends quelques instants.

Commencer

L'expérience commence immédiatement ou après une courte transition.

Éviter les longs écrans de présentation.

## 8. Le texte

Le texte doit être présenté seul ou presque.

Il doit disposer d'un espace important autour de lui.

Le texte peut apparaître progressivement.

L'animation doit être lente et discrète.

Le joueur doit pouvoir le lire sans distraction.

## 9. Le rythme

RÉSONANCE ne doit pas fonctionner au rythme d'une application classique.

Le rythme recommandé est :

apparition → pause → lecture → respiration → transition.

Le système ne doit pas automatiquement enchaîner les étapes trop rapidement.

## 10. Le joueur contrôle le rythme

Le joueur doit pouvoir décider quand poursuivre.

Par défaut :

- pas de compte à rebours ;
- pas de limite de temps ;
- pas de passage automatique obligatoire.

Le jeu doit accepter l'hésitation.

## 11. Passage du texte aux images

Cette transition constitue un moment important.

Le texte peut disparaître progressivement.

Les images apparaissent ensuite.

Le changement doit donner l'impression d'un déplacement :

du langage vers l'intuition.

## 12. L'écran de choix

L'écran de choix est l'un des écrans centraux de RÉSONANCE.

Il présente les images dans une composition claire.

Exemple conceptuel :

6 images

disposées de manière équilibrée, avec suffisamment d'espace entre elles.

Chaque image doit pouvoir être regardée sans que le joueur sache immédiatement laquelle est « la bonne ».

## 13. Ne pas numéroter les images

Les images ne doivent pas être présentées comme :

- Image A
- Image B
- Image C

La numérotation introduirait une logique de questionnaire.

Le choix doit être essentiellement visuel.

## 14. Interaction avec une image

Au survol sur ordinateur ou au toucher sur mobile :

- légère mise en évidence ;
- éventuellement agrandissement discret ;
- aucune animation spectaculaire.

Après sélection :

- l'image choisie devient dominante ;
- les autres s'effacent progressivement.

Cette transition matérialise :

« C'est celle-ci. »

## 15. Confirmation du choix

Le système ne doit pas immédiatement demander :

« Êtes-vous sûr ? »

Cela introduirait une logique administrative.

Le choix doit être assumé.

Si une confirmation est nécessaire, elle doit être naturelle :

Garder cette image

plutôt que :

Confirmer votre réponse.

## 16. L'expression

Après le choix, l'écran change de nature.

L'image choisie peut rester présente.

La question apparaît progressivement.

Exemple :

Qu'est-ce qui t'a attiré ici ?

Une zone de réponse peut apparaître sous la question.

## 17. L'écriture doit rester facultative

L'utilisateur doit pouvoir :

- répondre ;
- réfléchir ;
- passer ;
- revenir éventuellement plus tard.

Le jeu ne doit jamais transformer l'introspection en obligation d'écriture.

## 18. Le bouton « Passer »

Le bouton permettant de continuer sans répondre doit être disponible.

Mais il ne doit pas être visuellement dominant.

Le joueur doit sentir :

« Je peux ne rien dire. »

## 19. Le carnet

Le carnet constitue une seconde expérience.

Il ne doit pas ressembler à une base de données.

Il doit ressembler à la mémoire d'un parcours.

Les entrées doivent pouvoir être présentées sous forme de fragments :

- image ;
- phrase ;
- date ;
- quelques mots ;
- moments importants.

## 20. Le carnet comme espace de retour

Le carnet permet au joueur de revoir :

- ce qu'il a choisi ;
- ce qu'il a écrit ;
- ce qu'il a rencontré ;
- ce qui revient ;
- ce qui a changé.

Le carnet ne doit pas interpréter automatiquement le contenu.

Il conserve.

Il montre.

Il laisse regarder.

## 21. Les récurrences dans le carnet

Lorsqu'une récurrence est suffisamment significative, elle peut être mise en évidence visuellement.

Exemple :

plusieurs images similaires apparaissent avec un traitement graphique discret.

Le système peut indiquer :

Cela revient dans ton parcours.

Mais sans imposer d'explication.

## 22. L'angle mort

L'écran de l'angle mort doit visuellement se distinguer légèrement.

Pas par une alerte.

Pas par du rouge.

Pas par une rupture brutale.

Mais par une modification subtile :

- lumière ;
- composition ;
- espace ;
- rythme.

Le joueur doit sentir :

« Quelque chose change. »

sans savoir immédiatement quoi.

## 23. L'IA

Lorsque l'IA intervient, elle ne doit pas être présentée comme :

« L'IA analyse votre personnalité. »

Elle doit être présentée comme une présence éditoriale discrète.

Elle peut prendre la forme d'une question ou d'une proposition.

Exemple :

Une autre façon de regarder cela :

Et si ce qui te semblait être une limite était aussi un choix ?

## 24. Ne pas anthropomorphiser excessivement l'IA

RÉSONANCE ne doit pas créer un personnage artificiel qui prétend connaître intimement le joueur.

L'IA n'est pas :

- un thérapeute ;
- un coach ;
- un oracle ;
- un ami virtuel.

Elle est un outil de mise en perspective.

## 25. Direction artistique générale

La direction artistique doit être :

- élégante ;
- contemporaine ;
- immersive ;
- sobre ;
- légèrement mystérieuse ;
- chaleureuse ;
- organique.

Elle doit éviter l'esthétique :

- médicale ;
- thérapeutique ;
- ésotérique ;
- gamifiée ;
- corporate ;
- enfantine.

## 26. Une esthétique de l'entre-deux

RÉSONANCE doit visuellement se situer entre :

jeu

et

expérience artistique.

Entre :

interface

et

espace contemplatif.

Entre :

hasard

et

sens.

## 27. Couleurs

La palette doit être relativement réduite.

Elle peut être construite autour :

- de tons naturels ;
- de neutres chauds ;
- de nuances minérales ;
- de noirs doux ;
- de blancs cassés ;
- de quelques accents plus profonds.

La couleur doit servir le rythme.

Elle ne doit pas transformer chaque écran en signal.

## 28. Contraste

Le contraste doit être suffisant pour assurer la lisibilité.

Mais l'interface ne doit pas devenir visuellement agressive.

Le contraste peut varier selon les moments :

accueil → clair

résonance → calme

choix → focalisé

angle mort → plus dense

carnet → chaleureux

## 29. Typographie

La typographie doit exprimer :

- intelligence ;
- humanité ;
- simplicité ;
- élégance.

Une combinaison possible :

#### Typographie principale

Sans-serif contemporaine pour l'interface.

#### Typographie expressive

Une serif élégante peut être utilisée pour certains textes importants.

L'utilisation de deux familles maximum est recommandée.

## 30. Taille des textes

Les textes importants doivent être relativement grands.

Sur mobile, les phrases de résonance doivent pouvoir être lues sans effort.

L'espace autour du texte est aussi important que le texte lui-même.

## 31. Les images dominent les boutons

Lorsqu'une image et un bouton sont présents simultanément, l'image doit visuellement dominer.

Le bouton sert l'action.

L'image constitue l'expérience.

## 32. Boutons

Les boutons doivent être :

- simples ;
- lisibles ;
- peu nombreux ;
- cohérents.

Éviter les boutons très colorés et fortement « applicatifs ».

## 33. Icônes

Les icônes doivent être minimalistes.

Éviter les illustrations décoratives inutiles.

Chaque symbole doit être compréhensible immédiatement.

## 34. Animations

Les animations doivent avoir une fonction.

Elles peuvent servir à :

- ralentir ;
- révéler ;
- faire disparaître ;
- focaliser ;
- créer une transition.

Elles ne doivent pas servir à :

- divertir artificiellement ;
- montrer que l'application « travaille » ;
- remplir un espace vide.

## 35. Animation de choix

Lorsqu'une image est sélectionnée :

- les autres images diminuent légèrement ;
- l'image sélectionnée prend de l'importance ;
- la transition se fait sans rupture ;
- la question suivante apparaît.

La transition doit être suffisamment lente pour être ressentie mais suffisamment rapide pour ne pas devenir frustrante.

## 36. Responsive design

RÉSONANCE doit être conçu mobile-first.

Le téléphone est considéré comme le support principal de l'expérience.

L'interface doit ensuite s'adapter aux écrans plus larges.

## 37. Mobile

Sur mobile :

- une seule colonne lorsque nécessaire ;
- images suffisamment grandes ;
- zones tactiles généreuses ;
- texte lisible ;
- aucun élément essentiel placé trop près des bords ;
- navigation minimale.

## 38. Ordinateur

Sur ordinateur, l'espace disponible doit être utilisé pour renforcer la sensation d'immersion.

Les images peuvent être davantage espacées.

Les compositions peuvent devenir plus artistiques.

Mais l'expérience fonctionnelle doit rester identique.

## 39. Accessibilité

RÉSONANCE doit respecter les principes fondamentaux d'accessibilité :

- contraste suffisant ;
- taille de texte lisible ;
- navigation clavier ;
- alternatives textuelles lorsque nécessaires ;
- zones tactiles suffisamment grandes ;
- animations pouvant être réduites ;
- absence d'information transmise uniquement par la couleur.

## 40. Absence de surcharge

Un écran RÉSONANCE doit idéalement répondre à une seule question :

Qu'est-ce que le joueur doit regarder ou faire maintenant ?

Si plusieurs actions sont nécessaires simultanément, l'écran doit être réévalué.

## 41. Navigation

La navigation traditionnelle doit être réduite au minimum pendant une partie.

Le joueur ne doit pas avoir en permanence :

- menu ;
- profil ;
- paramètres ;
- statistiques ;
- notifications ;
- raccourcis.

Ces éléments appartiennent à l'environnement de l'application, pas au cœur de l'expérience.

## 42. Sortie temporaire

Le joueur doit pouvoir quitter une partie.

Le système doit conserver son état.

Lorsqu'il revient :

« Reprendre ta résonance »

peut être proposé.

## 43. Interruption

Une interruption n'est jamais présentée comme un échec.

Il n'y a pas :

Partie abandonnée.

Mais plutôt :

Ton parcours est conservé.

## 44. Écrans de transition

Les transitions peuvent être utilisées comme des respirations.

Exemple :

Prends ton temps.

ou simplement un espace visuel sans texte.

Le silence visuel fait partie du design.

## 45. La fin

La fin d'une partie doit être différente d'un écran de victoire.

Pas :

FÉLICITATIONS !

Pas :

SCORE : 87 %

Mais plutôt :

Voilà où ton chemin t'a conduit aujourd'hui.

Puis le joueur peut accéder à son carnet.

## 46. Le « Je suis »

Le « Je suis » doit bénéficier d'un traitement visuel particulier.

Il constitue un moment de formulation.

L'interface doit lui donner de l'espace.

Exemple :

JE SUIS

puis une formulation personnelle.

Le résultat doit pouvoir être conservé dans le carnet.

## 47. Le design sonore

Le son doit être optionnel.

S'il est utilisé, il doit être extrêmement discret.

Il peut accompagner :

- une transition ;
- une apparition ;
- une respiration.

Il ne doit jamais devenir une obligation.

## 48. Ambiance générale

L'expérience doit donner le sentiment :

d'entrer quelque part.

Pas :

d'ouvrir une application.

Cette distinction constitue l'un des objectifs majeurs de la direction artistique.

## 49. Ce que RÉSONANCE ne doit jamais devenir visuellement

RÉSONANCE ne doit pas ressembler à :

- un test de personnalité ;
- une application médicale ;
- une plateforme de coaching ;
- un jeu mobile classique ;
- un réseau social ;
- une application de méditation générique ;
- un questionnaire administratif.

## 50. Principe du « presque rien »

Lorsqu'un élément graphique n'apporte rien à :

- l'émotion ;
- la compréhension ;
- l'immersion ;
- l'action ;

il doit probablement disparaître.

L'espace vide est un élément graphique à part entière.

## 51. Identité visuelle

Le mot RÉSONANCE doit pouvoir fonctionner seul comme une identité.

Le logo doit rester simple.

Il peut éventuellement exploiter :

- une vibration ;
- une onde ;
- une répétition ;
- une déformation ;
- une forme qui se propage.

Mais sans tomber dans le symbole littéral de l'onde sonore.

## 52. Le mouvement comme langage graphique

Le mouvement peut devenir un élément identitaire.

Une forme peut :

apparaître → vibrer → se déplacer → se transformer → disparaître.

Cela permet de traduire graphiquement le principe même de résonance.

## 53. Règle de cohérence

Chaque élément de l'interface doit appartenir au même univers.

L'utilisateur doit reconnaître immédiatement :

« Je suis dans RÉSONANCE. »

sans avoir besoin de voir le logo.

## 54. Design system

Le développement devra disposer d'un système graphique comprenant au minimum :

- couleurs ;
- typographies ;
- tailles ;
- espacements ;
- boutons ;
- champs ;
- cartes ;
- états de sélection ;
- transitions ;
- composants d'image ;
- composants de texte ;
- composants du carnet ;
- messages système.

## 55. États des composants

Chaque composant interactif doit prévoir :

- état normal ;
- survol ;
- focus ;
- sélection ;
- désactivation ;
- erreur éventuelle ;
- chargement.

Le traitement doit rester discret et cohérent avec l'univers de RÉSONANCE.

## 56. Règle de développement UX

Une fonctionnalité ne doit pas être ajoutée simplement parce qu'elle est techniquement possible.

Avant chaque ajout, trois questions doivent être posées :

Est-ce utile ?

Est-ce cohérent avec l'expérience ?

Est-ce que cela rapproche ou éloigne le joueur de lui-même ?

## 57. Critère ultime de l'interface

Une bonne interface RÉSONANCE doit devenir progressivement invisible.

Le joueur doit finir par ne plus penser :

« J'utilise une application. »

mais :

« Je suis en train de regarder quelque chose en moi. »

## 58. Synthèse UX/UI

L'expérience visuelle repose donc sur sept principes :

1. ESPACELaisser respirer.

2. SILENCENe pas solliciter inutilement.

3. IMAGEFaire du visuel le cœur du choix.

4. RYTHMELaisser au joueur le temps.

5. MYSTÈRENe pas tout expliquer.

6. SOBRIÉTÉÉviter la gamification artificielle.

7. SOUVERAINETÉNe jamais prendre la place du joueur.

## 59. Principe directeur final

RÉSONANCE doit être suffisamment beau pour donner envie d'y entrer, suffisamment ludique pour donner envie d'y rester, et suffisamment discret pour que le joueur finisse par oublier l'application.

L'interface n'est pas le spectacle.

Le joueur et ce qui résonne en lui sont le spectacle.
